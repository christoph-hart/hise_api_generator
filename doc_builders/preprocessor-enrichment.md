# Preprocessor Enrichment Pipeline

**Purpose:** Maintain the catalogue of supported HISE preprocessor macros and publish it to the documentation website and MCP server.

**Authored source:** `hi_backend/backend/PreprocessorDatabase.cpp`

**Generated REST snapshot:** `tools/api generator/preprocessor_enrichment/resources/preprocessor.json`

**Generated website sources:** `tools/api generator/preprocessor_enrichment/output/*.md`

---

## Pipeline Overview

```text
HISE C++ source and exporter templates
        |
  [Step 1] Research the macro
        |    - Definitions, defaults, usages, build targets
        |    - Exporter configuration and compatibility impact
        |
  [Step 2] Author an Entry in PreprocessorDatabase.cpp
        |    - Description and category
        |    - Default and compiled value
        |    - Hot reload, auto config, and vestigial flags
        |    - Cross-references
        |
  [Step 3] Build and run HISE
        |
  [Step 4] Fetch GET /api/status/preprocessors?verbose=true
        |
        v
preprocessor_enrichment/resources/preprocessor.json
        |
        +-- publish.py
        |       |
        |       v
        |   preprocessor_enrichment/output/*.md
        |       |
        |       v
        |   Documentation website
        |
        +-- collect_mcp.py
                |
                v
            MCP preprocessor.json
```

The C++ database is the source of truth. The JSON and generated Markdown files must not be edited as substitutes for changing the database.

## Source And Output Ownership

| Path | Role | Edit manually? |
|------|------|----------------|
| `hi_backend/backend/PreprocessorDatabase.cpp` | Macro entries and documentation | Yes |
| `hi_backend/backend/PreprocessorDatabase.h` | Entry schema, categories, and serialization | Only when extending the schema |
| `preprocessor_enrichment/resources/static/*.md` | Category introductions and landing-page prose | Yes |
| `preprocessor_enrichment/resources/regenerate.py` | Cross-platform REST snapshot regeneration | Yes |
| `preprocessor_enrichment/resources/preprocessor.json` | Snapshot returned by the REST endpoint | No |
| `preprocessor_enrichment/output/*.md` | Category pages generated by `publish.py` | No |

`publish.py` deletes all Markdown files in `preprocessor_enrichment/output/` before regenerating them. Any manual changes there will be lost.

## Step 1: Research The Macro

Do not document a macro from its name or default definition alone. Search the full HISE source tree and establish its actual behaviour first.

### Required research

1. Find every definition and fallback definition.
2. Find every conditional compilation guard and runtime read.
3. Check all three build configurations:
   - HISE IDE: `USE_BACKEND=1`
   - Exported plugin: `USE_FRONTEND=1`
   - Project DLL: `HI_EXPORT_AS_PROJECT_DLL=1`
4. Search the project exporter and Projucer templates to determine whether the value is set automatically.
5. Search `ExtraDefinitions` handling to determine whether the value can be supplied per project.
6. Determine the effective default when the macro is not explicitly defined.
7. Determine whether changing the value affects binary layout, saved data, preset compatibility, audio output, CPU use, memory use, or optional dependencies.
8. Find related modules, scripting APIs, scriptnode nodes, UI components, language pages, and preprocessors.

### Classification decisions

Answer these questions before authoring the entry:

| Question | Entry field |
|----------|-------------|
| Which user-facing area does it affect? | `Category` |
| What happens when it is enabled or changed? | `brief`, `description` |
| What value is used when it is not configured? | `defaultValue` |
| What value was compiled into this HISE binary? | `value` |
| Does HISE read an ExtraDefinitions override dynamically? | `supportsHotReload` |
| Does the exporter derive or write the value? | `autoConfig` |
| Is the macro retained but no longer read? | `vestigal` |
| Which reference pages explain affected features? | `links` |

The `vestigal` spelling is part of the existing serialized schema. Do not correct it in an individual entry.

### Research gate

Do not continue until all of the following are known:

- The effective default value.
- The compiled value expression passed to `.withValue()`.
- Every build target in which the macro matters.
- Whether the exporter controls it.
- Whether hot reload is genuinely implemented.
- Whether it is active or a retained no-op.
- The user-visible consequences of changing it.

## Step 2: Author The Database Entry

Add new entries before this marker at the end of `PreprocessorDatabase.cpp`:

```cpp
// <-- ADD NEW PREPROCESSORS DEFINITIONS BEFORE THIS LINE
```

Use the fluent `Entry` format:

```cpp
data["EXAMPLE_PREPROCESSOR"] = Entry()
	.withCategory(Category::AudioProcessing)
	.withBrief("One sentence describing the practical effect of the macro.")
	.withDescriptionLine("Explain what changes, when it is useful, and the important runtime or build implications.")
	.withDescriptionLine("> Warn about compatibility, performance, dependencies, or configuration requirements when necessary.")
	.withDefault(0)
	.withValue(EXAMPLE_PREPROCESSOR)
	.withCrossReference(LinkType::Module, "ExampleModule", "feature whose behaviour changes")
	.withCrossReference(LinkType::Preprocessor, "RELATED_PREPROCESSOR", "related configuration switch");
```

Tabs are required for indentation in C++ files.

### Category

Choose an existing category from `PreprocessorDataBase::Category`:

- `AudioProcessing`
- `AutomationAndMacros`
- `BackwardsCompatibility`
- `DebugAndProfiling`
- `DspAndFilters`
- `LicensingAndExpansions`
- `ModulatorSlots`
- `PluginType`
- `PolyphonyAndChannels`
- `PresetAndState`
- `SamplerAndStreaming`
- `ThirdPartyModules`
- `UiAndGraphics`

Adding a category requires coordinated changes to the `Category` enum, `getCategoryNames()`, and `getCategorySlugs()` in `PreprocessorDatabase.h`. The three lists must remain in the same order. Also add a matching category introduction:

```text
preprocessor_enrichment/resources/static/<category-slug>.md
```

Prefer an existing category unless the macro represents a genuinely new documentation area.

### Brief

The brief is one sentence that describes the practical effect. It should:

- Start with an active verb.
- Be understandable without reading C++.
- Distinguish the macro from similarly named switches.
- Avoid repeating the macro name.

### Description

Use one or more `.withDescriptionLine()` calls. Cover the information that affects a user's decision to change the value:

- Behaviour when enabled and disabled.
- Relevant build targets or plugin types.
- CPU, memory, binary-size, or latency implications.
- Required SDKs, libraries, files, or exporter settings.
- Compatibility effects on presets, saved indices, audio output, or project state.
- Whether HISE and the exported plugin must use matching values.

Use a final blockquote line for a warning or strong operational recommendation when appropriate. Follow `tools/api generator/style-guide/general.md`, except that naming the documented preprocessor is necessarily allowed in this reference.

All authored text must be ASCII-only and use British English.

### Default And Value

`.withDefault(value)` records the value used when the user has not configured the macro. It is documentation metadata and is also used by the REST endpoint's `skipDefaults` filter.

`.withValue(MACRO)` records the value compiled into the running HISE binary. For hot-reloadable entries, the REST endpoint can replace this with the current ExtraDefinitions value.

Do not use the current local build configuration as the documented default. Confirm the fallback definition or exporter behaviour.

### Optional Macro Fallbacks

The database constructor must compile in every backend configuration. If a macro only exists when an optional SDK or module is available, add a fallback near the top of `PreprocessorDatabase.cpp`:

```cpp
#ifndef EXAMPLE_PREPROCESSOR
#define EXAMPLE_PREPROCESSOR 0
#endif
```

Only add this when the macro can legitimately be undefined. Do not mask a missing required include or an incorrect build configuration with a fallback.

### Hot Reload

Add `.withHotReload()` only when the implementation reads the project value through the dynamic preprocessor system, such as `HISE_GET_PREPROCESSOR` or `MainController::getExtraDefinitionsValue()`.

An ExtraDefinitions value by itself does not imply hot reload. Most macros still require recompilation because the C++ preprocessor has already removed or changed code.

### Auto Config

Add `.withAutoConfig()` when `CompileExporter` or a project template derives and writes the macro from another project setting. Explain the controlling setting in the description so users know whether they should edit ExtraDefinitions manually.

### Vestigial Macros

Add `.withVestigal()` only when the macro remains defined for compatibility but no active code reads it. The description must state that changing it has no effect and explain why it remains in the catalogue.

Do not classify a platform-specific or optional macro as vestigial merely because it is inactive in the current build.

### Cross-References

Use `.withCrossReference()` for pages that explain an affected feature or a closely related setting:

```cpp
.withCrossReference(LinkType::UI, "FloatingTiles.PresetBrowser", "affected preset browser UI")
.withCrossReference(LinkType::Module, "StreamingSampler", "sampler behaviour controlled by this macro")
.withCrossReference(LinkType::Scriptnode, "filters.convolution", "scriptnode equivalent")
.withCrossReference(LinkType::ScriptingApi, "Engine.getHostBpm", "runtime API affected by the setting")
.withCrossReference(LinkType::Language, "arrays", "related language feature")
.withCrossReference(LinkType::Preprocessor, "RELATED_MACRO", "related compile-time setting")
```

The serializer converts these into canonical `$DOMAIN.Target$ -- rationale` tokens. Every rationale should explain the relationship rather than merely saying "related".

Cross-references to other preprocessors stay on the generated preprocessor pages. Cross-references to other domains are also used by `publish.py` to inject incoming preprocessor references into their target pages.

### Authoring gate

Before rebuilding, verify:

- The macro name matches the C++ identifier exactly.
- The entry uses an existing category or includes all required new-category changes.
- The brief is one sentence.
- The description covers requirements and consequences without C++ implementation leakage.
- `.withDefault()` matches the actual default.
- `.withValue()` uses the macro rather than a duplicated literal.
- Optional flags are supported by source evidence.
- Cross-reference targets use canonical identifiers.
- Text and code are ASCII-only.

## Step 3: Build And Run HISE

`PreprocessorDataBase` is compiled into the HISE backend. Rebuild HISE after editing the C++ database, then launch the HISE IDE and start its REST server.

The REST endpoint reports metadata from the running binary. Fetching from an older binary will silently reproduce the old database, so confirm that the running HISE instance contains the new build.

HISE builds and tests are run manually by the maintainer using the Projucer-generated IDE projects.

## Step 4: Refresh The REST Snapshot

The default REST server URL is `http://localhost:1900`. Run the cross-platform regeneration script (shown from the repository root):

```bash
python "tools/api generator/preprocessor_enrichment/resources/regenerate.py"
```

The script locates `preprocessor.json` relative to its own file, so the output path does not depend on the current working directory. It invokes `curl`, writes the response to a temporary file, validates the response, and replaces the existing snapshot only when the request succeeds. Python 3 must be installed and `curl` must be available on `PATH`; current macOS and Windows installations include `curl` by default.

To fetch from a REST server using a different host or port:

```bash
python "tools/api generator/preprocessor_enrichment/resources/regenerate.py" --url "http://localhost:1901/api/status/preprocessors?verbose=true"
```

The response shape is:

```json
{
  "success": true,
  "preprocessors": {
    "EXAMPLE_PREPROCESSOR": {
      "value": 0,
      "defaultValue": 0,
      "autoConfig": false,
      "supportsHotReload": false,
      "category": "Audio Processing",
      "category-slug": "audio-processing",
      "brief": "...",
      "description": "...",
      "valueRange": "",
      "vestigal": false,
      "crossRefs": []
    }
  },
  "logs": [],
  "errors": []
}
```

The endpoint supports two diagnostic variants:

```bash
# Compact name-to-runtime-value map
curl -s "http://localhost:1900/api/status/preprocessors"

# Show only runtime values that differ from their documented defaults
curl -s "http://localhost:1900/api/status/preprocessors?verbose=true&skipDefaults=true"
```

Always use `verbose=true` without `skipDefaults=true` for the checked-in documentation snapshot.

### Snapshot gate

Before publishing, verify:

- `success` is `true`.
- `errors` is empty.
- The new or changed macro appears under `preprocessors`.
- Its serialized fields match the C++ entry.
- Existing entries were not unexpectedly removed.
- The file contains the full catalogue, not a `skipDefaults=true` subset.

---

## Step 5: Generate And Validate Website Pages

`publish.py` reads the REST snapshot, groups entries by `category-slug`, and regenerates `preprocessor_enrichment/output/*.md`. It then resolves canonical links and publishes the pages with the other documentation domains.

From `tools/api generator/` run:

```bash
python publish.py <website-output-dir> --strict
```

The `--strict` flag fails on unresolved links. Review all preprocessor-related warnings, especially malformed or unresolved cross-references and missing category introduction files.

Important: `publish.py --dry-run` still regenerates `preprocessor_enrichment/output/*.md`. It prevents writes to the final website output, but it is not read-only for generated pipeline files.

### Website gate

- No malformed preprocessor cross-reference warnings.
- No unresolved cross-reference errors.
- No missing static category introduction warnings.
- The macro appears under the expected category.
- Vestigial macros appear under the category's `Deprecated` section.
- The default, hot reload, and auto config values render correctly.

---

## Step 6: Publish MCP Data

`collect_mcp.py` copies the REST snapshot unchanged into the MCP data directory alongside the other enrichment outputs:

```bash
python collect_mcp.py <mcp-data-dir>
```

Validate all enrichment inputs without writing the MCP output:

```bash
python collect_mcp.py --dry-run
```

The MCP collector does not regenerate the snapshot from HISE. Step 4 must be completed first.

## Updating An Existing Entry

Use the same research and publication gates when changing existing documentation:

1. Confirm that the implementation changed or that the existing text is inaccurate.
2. Edit the entry in `PreprocessorDatabase.cpp`.
3. Rebuild and run HISE.
4. Refresh the complete verbose REST snapshot.
5. Publish with strict link validation.
6. Refresh MCP data when required.

Never patch the generated JSON alone. The next REST fetch would overwrite the correction.

---

## Adding A New Category

Adding a category is a coordinated schema and content change:

1. Add the enum value before `numCategories` in `PreprocessorDatabase.h`.
2. Add its display name at the same index in `getCategoryNames()`.
3. Add its slug at the same index in `getCategorySlugs()`.
4. Add `preprocessor_enrichment/resources/static/<slug>.md` with YAML frontmatter containing a `description`.
5. Add at least one entry using the category.
6. Rebuild, fetch, and publish.
7. Confirm the category appears on the generated landing page.

The enum, display-name array, and slug array are indexed in parallel. An ordering mismatch assigns incorrect metadata to every category after the mismatch.

## Current Limitations

- There is no checked-in scanner that discovers undocumented macros automatically.
- The `UNPROCESSED_BEGIN` and `UNPROCESSED_END` block in `PreprocessorDatabase.cpp` is currently an empty placeholder.
- The REST endpoint exposes only entries registered in the database. It cannot report missing entries.
- `ServerUnitTests.cpp` validates endpoint shape and filtering, not documentation completeness or factual accuracy.
- The JSON snapshot depends on the compile-time values of the HISE binary used to produce it.
- `valueRange` is serialized by the schema but currently has no fluent authoring method and is empty for existing entries.

Until automated discovery exists, full-source research and review are required whenever the catalogue is extended.
